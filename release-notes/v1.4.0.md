# v1.4.0 (2026-04-27)

This release introduces capture previews, a session-scoped history browser, and a dramatically faster full-page capture engine — replacing tile stitching with a single-shot Chrome debugger approach.

### ✨ New Features

- **macOS-style capture preview**: A thumbnail slides in from the bottom-right after every capture. Click it to expand into a full modal with Download, Copy, and Close actions. Enabled by default; can be turned off in Settings.
- **Capture history browser**: Every capture is persisted to session storage and accessible via a horizontal thumbnail strip inside the preview modal. The strip backdrop blurs and tints to echo the active capture's colors. Entries are kept within an 8 MB / 30-capture budget — larger captures retain fewer slots automatically.
- **Remove captures from history**: Each capture in the preview modal has a Remove button. Clicking it shows an inline "Remove this capture from history?" confirmation — confirm to permanently drop the entry and promote the next capture, or cancel to return to the normal toolbar without disturbing anything.
- **"View History" link in the floating panel**: A quiet footer link in the floating panel opens the preview modal at the most recent capture so you can browse history without taking a fresh screenshot.
- **CDP-powered full-page capture**: Full-page screenshots no longer require tile stitching. The extension now uses Chrome's debugger API to resize the emulated viewport to the full document height and capture everything in one shot — eliminating the 600 ms-per-tile delays, multi-second waits on tall pages, and stitching seam artifacts.

### 🎨 Improvements

- **Panel hides during full-page and viewport capture**: The floating panel now suppresses itself before any full-page or viewport capture so it doesn't appear in the output.
- **Preview Captures on by default**: New installs have "Preview Captures" switched on so the thumbnail appears out of the box without changing settings.

### 🐛 Fixes

- **Correct filename when re-downloading from preview**: The download triggered from the preview modal now uses the capture's source type (element, region, viewport, page) in the filename, matching the original download convention.
- **"Select Element" label consistency**: The success-state button in the floating panel now correctly reads "Select Element".
- **Toast notifications for all capture outcomes**: Success and error toasts now fire reliably across all capture flows.
- **CDP stability hardening**: `captureBeyondViewport` is now set explicitly so off-screen content is always included; a "Another debugger is attached" conflict now surfaces a clear user-facing message instead of a raw Chrome error; scroll position is restored to the top in the cleanup block regardless of errors.
- **Preview modal remove flow**: Guarded against missing asset IDs, debounced the confirm button across async deletes, and falls back to closing the modal gracefully if loading the replacement capture fails.
- **Preview clipboard copy**: Wrapped the re-encode error path in a proper `Error` so failures surface a real message instead of "Failed to copy: undefined"; snapshot the active asset at entry so a concurrent capture swap can't desync what gets copied from what the modal shows.
